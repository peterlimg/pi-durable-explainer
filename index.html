Pi Durable

Pi Durable is a library for AI agents. It keeps the work of the agent safe. If the program stops, the agent continues from the last saved step.

Package: @earendil-works/pi-durable (version 1.0.4). It is part of the Pi agent project.

CautionThe library is experimental. The API can change between releases without a warning.

What it does

An AI agent does work in many steps. It reads your message. It asks a model. It runs tools. It writes an answer.

Pi Durable saves each step to storage before it shows the result. This is the main rule. Storage can be memory, SQLite, or JSONL files.

If the process stops during a step, nothing is lost. You open the storage again. The agent finds the last saved step and continues.

Problems it solves

Each row shows a problem with a normal agent. It shows what Pi Durable does.

The program stops during a turn

Problem. The agent loses the work. You must start again.

Pi Durable. Tasks save a checkpoint at each step. resume() continues the work.

A write stops halfway

Problem. Some data is saved and some is not. The state is broken.

Pi Durable. A commit is atomic. It saves all changes or no changes.

The same message is sent two times

Problem. A retry after a crash runs the work two times.

Pi Durable. Give a requestId. The second send finds the first submission.

You send a message while the agent works

Problem. The message is lost, or it breaks the current run.

Pi Durable. The message goes into an inbox. It is a “steer” (join now) or a “follow-up” (after the answer).

The conversation becomes too long

Problem. The model rejects the request. The context is too large.

Pi Durable. Compaction makes a summary of old entries. Reset starts a new context. Old entries stay in storage.

You must stop work that has sub-work

Problem. Child work continues after you stop the parent.

Pi Durable. Abort goes from the bottom up. Each task stops its child tasks first.

You do not know the cost

Problem. Spend on the model is not recorded.

Pi Durable. The pi.usage document records spend for each conversation.

Words to know

Harness
The main object. It opens one storage and runs agents on it.
Conversation
A list of entries. You can make more conversations and fork them.
Entry
One record in a conversation. You cannot change it after it is saved.
Commit
One atomic write. It can add entries, change documents, and make tasks.
Document
Typed JSON state next to the conversation, for example the inbox or the cost.
Task
A step-by-step job that saves a checkpoint at each step.
Submission
Something you send to a conversation. You can wait for it.
Extension
A named set of tools, prompt sections, hooks, and tasks.
